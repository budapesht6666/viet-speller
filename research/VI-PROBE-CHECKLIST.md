# Протокол замера vi-VN

Этап 0 из `PLAN.md`. Все факты о распознавании в Speller сняты на `en-US`;
здесь проверяем, какие из них верны для вьетнамского и какие упражнения
вообще возможны. До замера код уроков не пишем.

## Что нужно

- Ноутбук с проектом: `npm install` уже сделан.
- iPhone. Если есть — Android с Chrome.
- Тихая комната. Для части заданий нужна колонка ноутбука: она играет
  образец, телефон его слушает.

## Запуск

```powershell
npm run probe:phone
```

Команда поднимает две вещи, и обе нужны:

- **сервер пробы** на `http://localhost:5174` — отдаёт страницу и образцы;
- **туннель Cloudflare** к нему — даёт адрес `https://….trycloudflare.com`.
  Без https iPhone не даёт ни микрофон, ни распознавание, а адрес из
  домашней сети (`http://192.168.x.x`) защищённым не считается.

Когда туннель подключится, в терминале появятся QR-код и адрес. Телефону
не обязательно быть в той же Wi-Fi: туннель идёт через интернет.

- **iPhone**: навести камеру на QR-код и открыть ссылку в Safari. Если
  страница не открылась — подождать 10–20 секунд и обновить: новый адрес
  расходится по DNS не мгновенно.
- **Ноутбук**: открыть `http://localhost:5174/vi-probe.html` — с него
  играет образец.

Окно терминала не закрывать до конца замера. Адрес туннеля при каждом
запуске новый, и ярлык на домашнем экране от прошлого запуска ведёт в
никуда.

Если нужно по отдельности: `npm run probe` и `npm run tunnel:probe`.

## Один раз перед замером — iPhone

1. **Настройки → Основные → Клавиатура → Включить диктовку.** Выключенная
   диктовка глушит распознавание молча: API есть, событий нет.
2. **Настройки → Основные → Клавиатура → Клавиатуры → Новые клавиатуры →
   Tiếng Việt.** Это гипотеза, а не измеренный факт: возможно, без
   вьетнамского языка диктовки `vi-VN` отдаёт пустоту. Если с клавиатурой
   и без неё результат разный, это тоже результат — запиши его.

## Кто говорит

Переключатель «Кто говорит» на телефоне. Он попадает в отчёт, и прогоны
с разным голосом не смешиваются.

| Режим | Что делать | Для чего |
|---|---|---|
| образец с другого устройства | на телефоне «Слушать», на ноутбуке на том же задании «Образец». Ноутбук примерно в метре от телефона | **Главный режим.** Тон образца известен точно, только так можно ответить на вопрос про неверный тон |
| я сам | сказать текст с экрана. Перед этим можно нажать «Образец» и повторить | Как будет в жизни: выговор начинающего |
| носитель языка | попросить соседа или хозяина квартиры прочитать с экрана | Если найдётся — самый ценный прогон для тонов |
| образец с этого же телефона | «Слушать», потом «Образец» на том же телефоне | Побочный опыт: слышит ли телефон собственный динамик. Если да, тренироваться можно без второго устройства |

Голос образца (HoaiMy или NamMinh) лучше один на весь прогон.

## Ход прогона

1. «Включить распознавание», разрешить микрофон. Сессия одна на весь
   замер — так будет и в приложении.
2. На каждом задании: **«Слушать»** → сказать или проиграть образец →
   дождаться, пока текст в окне перестанет меняться (финал приходит секунды
   через две после тишины) → **«Готово»** → «Дальше».
3. Не получилось — «Слушать ещё раз». Засчитывается последняя попытка, число
   попыток видно в отчёте.
4. После последнего задания — **«Скопировать отчёт»**. В отчёте сводка,
   таблица заданий и полный журнал событий.
5. Отчёт вставить в `research/VI-PROBE-RESULTS.md` под заголовком прогона
   или прислать в чат.

Результаты сохраняются в браузере: случайная перезагрузка ничего не стирает.
У вкладки и у иконки домашнего экрана хранилища разные — так и должно быть,
это два разных прогона.

## Прогоны

| # | Где | Кто говорит | Обязателен |
|---|---|---|---|
| A | iPhone, вкладка Safari | образец с ноутбука | да — контрольный |
| B | iPhone, **с иконки домашнего экрана** | образец с ноутбука | да — так будет жить приложение |
| C | iPhone, с иконки | я сам | да |
| D | Android Chrome | образец с ноутбука | если есть телефон |
| E | iPhone, с иконки | носитель языка | если получится |

Перед прогоном B: «Поделиться» → «На экран Домой», полностью закрыть Safari,
открыть иконку. В блоке «Окружение» должно стоять «с иконки (standalone)».
Если там «вкладка браузера», прогон недействителен.

## Как читать отчёт

Что решает каждый ответ — из `PLAN.md`, этап 0:

| Строка отчёта | Если да | Если нет |
|---|---|---|
| **interim / финал**: первый interim приходит за доли секунды | Проверка по interim, как в Speller | Упражнения ждут финала, в интерфейсе явное «слушаю…» |
| **диакритика**: есть почти во всех ответах | Сравнение с тонами возможно | Тон по распознаванию не проверить — только упражнения на слух |
| **неверный тон**: «как сказано» | Подсказка «слово верно, тон другой» честна | Движок исправляет тон по смыслу. Пишем в README: тон проверяет только ухо |
| **шесть тонов ma**: тон совпал у большинства | Тренировка тонов голосом | Тоны — только на слух |
| **одиночный слог** узнан | Алфавит и тоны голосом | Отдельные звуки только на слух, голосом — в составе слова |
| **числа** цифрами | В профиль `vi` нужна свёртка «цифры ↔ слова» | Числа сравниваются как слова |
| **фразы** целиком | Упражнение «скажи фразу» | Фраза проверяется по частям |

Кроме сводки стоит выписать из журнала:

- `onresult len=… idx=…` — копит ли Safari всю сессию в одном результате
  (`len=1` всё время) или заводит новый на каждую фразу. От этого зависит
  разбор хвоста в приложении.
- `alts=` и confidence в `interim` и в `FINAL` — для `en-US` было `alts=1`
  и `0.00`.
- `SR onend` и `авторестарт` — рвётся ли сессия между заданиями.
- Ошибки `SR ONERROR`, кроме `no-speech` и `aborted`.
